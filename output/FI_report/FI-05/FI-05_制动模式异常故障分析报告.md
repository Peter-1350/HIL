# FI-05 制动模式异常故障分析报告

## 结论

本轮记录中，注入接口 `Veh_1.Driver.BrakeMode` 在全部 324 个样本、约 32.3 s 内恒为 `0`，变化次数为 `0`。因此，本轮实际覆盖的是**BrakeMode 卡死/冻结为 0**的场景；没有记录到其他模式码、模式跳变或非法模式码，不能评价不同 BrakeMode 枚举之间的切换、拒绝和恢复逻辑。

在 BrakeMode 恒为 0 的前提下，制动踏板仍可正常驱动制动硬件输出并产生车辆减速：

- 制动踏板 100% 时，`BRK_Main=4 V`、`BRK_Auxi=2 V`、两路制动继电器均为 2；
- 15.700～19.600 s 的第二段满制动中，车速由约 89.47 降至 35.69，MCU 扭矩保持为 0；
- 制动踏板 0% 时，输出恢复 1/0.5 V，继电器恢复为 0。

这说明**模式值 0 没有阻断本次记录中的踏板制动通路**。若 0 是故意注入的卡死值，则已观察到该故障在当前工况下不会使制动输出失效；若原计划应切换 BrakeMode 而记录却始终为 0，则应检查注入脚本或记录配置。

`BrakeMode` 的枚举定义没有包含在记录配置中，因此不能将数值 0 解释为具体的制动模式名称，也不能正式判定它是合法还是非法模式码。

| --- | --- | ---: | ---: | ---: | --- | --- | --- |
| 初始化基线 | 0.000～4.000 | 0 | 0% | 0% | 1/0.5 V，继电器 0 | 约 0 → 约 0 | Key/制动准备前状态。 |
| 准备制动 | 4.000～8.000 | 0 | 100% | 0%～50% | 4/2 V，继电器 2 | 约 0 → 约 0 | 车辆尚未起步，验证输出通路。 |
| 加速与滑行 | 8.000～15.700 | 0 | 0% | 50%/80%后回到0% | 1/0.5 V，继电器 0 | 约 0 → 89.87 | 扭矩峰值约 360.3，车辆起步并加速。 |

第二段满制动开始时 MCU 扭矩已为 0，因而该段主要验证制动输出和车辆减速，而不是“带驱动扭矩下 BrakeMode 对制动仲裁”的行为。

## 接口一致性

本轮中踏板到硬件输出的映射保持正确：

```text
BRK_Main = 1 + 0.03 × clip(BrakePedal, 0, 100)
BRK_Auxi = BRK_Main / 2
ACC_Main = 1 + 0.03 × clip(AccPedal, 0, 100)
ACC_Auxi = ACC_Main / 2
```

- BRK 主/辅映射最大残差为 0；ACC 主/辅映射最大残差仅为浮点误差（约 `4.45e-16`）。
- 两路制动继电器在 324 个样本上完全一致，无失配。
- 前电机实际扭矩、前轴扭矩管理量和 MCU 扭矩输出同值变化；最大值均为约 360.3。

这表明本次 BrakeMode 固定为 0 时，基础踏板接口与扭矩执行通道没有出现数值失配。

## 故障判定

| 检查项 | 判定 | 依据 |
| --- | --- | --- |
| BrakeMode 卡死为 0 是否被记录 | 通过观察 | 全部 324 样本均为 0。 |
| BrakeMode=0 下的制动踏板输出 | 通过 | 100% 踏板对应 4/2 V 和双继电器激活。 |
| BrakeMode=0 下的车辆减速 | 通过观察 | 满制动段车速 89.47 → 35.69。 |
| BrakeMode 跳变/非法码处理 | 无法判定 | 本轮没有任何非零 BrakeMode 值。 |
| BrakeMode 对扭矩仲裁的因果影响 | 无法判定 | 未记录 VCU 扭矩请求、制动状态机或模式枚举。 |
| 模式异常诊断/降级状态 | 无法判定 | 缺少诊断位和 BrakeMode 内部状态。 |

## 下一轮建议

1. 明确 BrakeMode 枚举表、合法范围、默认/失效安全值及非法码处理要求。
2. 在 Key=1、Gear=1、AccPedal=固定值、BrakePedal=固定值的条件下，单独施加每个有效模式码和至少一个非法码，避免模式与踏板同时变化。
3. 分别执行卡死 0、卡死非零、非法码、行驶中跳变和短脉冲模式切换，记录模型状态机、故障位、扭矩请求与制动分配。
4. 增加 `VCU_TqReqCmd`、制动扭矩/再生扭矩、机械制动分配、BrakeMode 内部状态及诊断信号；当前数据只能证明外部踏板输出正常，不能验证制动模式仲裁。
