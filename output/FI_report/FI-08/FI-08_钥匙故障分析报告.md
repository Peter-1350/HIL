# FI-08 钥匙故障分析报告

> 本报告基于早期约 100 ms 记录保留用于追溯。最新 20 ms 试验结果见 [FI-08_故障传播图_20ms.md](FI-08_故障传播图_20ms.md) 与 [FI-08_故障指纹与最小诊断集_20ms.md](FI-08_故障指纹与最小诊断集_20ms.md)。

## 结论

本轮共验证三类钥匙故障，均能从 Key 边沿、动力扭矩、电流和车速中明确识别：

| 故障 | Key 波形 | 结果 | 判定 |
| --- | --- | --- | --- |
| 突然熄火 | 1 → 0（18.200 s） | MCU/前电机扭矩在约 0.200 s 内由 143.25 降至 0；母线电流同步由约 555.7 降至约 3.2。 | 动力切断有效；是否满足安全时间指标需对照项目阈值。 |
| 失灵脉冲 | 1 → 0 → 1（55.200～55.900 s） | Key 置 0 后约 0.400 s 扭矩归零；Key 恢复 1 后，在至少约 5.2 s 内仍保持零扭矩，即使挡位=1、油门=100%、制动=0。 | 未出现脉冲后的非预期自动恢复驱动；呈现关断锁存/上层请求未恢复特征。 |
| 错误唤醒 | 0 → 1 → 0（69.600～70.300 s） | 挡位=0、油门=0%、制动=100% 保持不变，扭矩为 0，母线电流接近零，车速仅有静止附近波动。 | 未观察到错误唤醒导致的非预期驱动。 |

本轮的安全行为总体符合“Key 失效不应持续驱动、错误唤醒不应产生驱动力”的预期。需要保留一个限制：记录中未包含 VCU 扭矩请求、钥匙状态机、模型复位和诊断故障位，因此无法确定失灵脉冲后的零扭矩究竟由 Key 关断锁存、上层 VCU 不再请求扭矩，还是两者共同造成。

## 故障事件分析

### 1. 突然熄火（1 → 0）

故障发生于相对时间 18.200 s。当时 `Gear_Button=1`、`AccPedal_perc=100%`、`BrakePedal_perc=0%`，车辆处于驱动状态，车速约 160.68，MCU 扭矩约 143.25。

| 时间 | Key | MCU/前电机扭矩 | MCU 母线电流 | 车辆状态 |
| --- | ---: | ---: | ---: | --- |
| 18.100 s（故障前） | 1 | 143.83 | 556.94 | 车速 160.23，持续行驶。 |
| 18.200 s（Key 置 0） | 0 | 143.25 | 555.70 | 当采样点仍有残余驱动。 |
| 18.300 s | 0 | 142.68 | 554.56 | 残余扭矩继续下降。 |
| 18.400 s | 0 | 0 | 3.23 | 扭矩和驱动电流已切断。 |

结论：从 Key 下降沿到扭矩小于 1 的观测延迟约 0.200 s。车速在惯性下由 160.68 短暂升至约 161.66，随后下降；这属于扭矩切断后的惯性响应，不是持续驱动。

### 2. 失灵脉冲（1 → 0 → 1）

故障发生于 55.200～55.900 s，Key 低电平持续约 0.700 s。故障前后驾驶工况保持 `Gear_Button=1`、`AccPedal_perc=100%`、`BrakePedal_perc=0%`。

| 时间 | Key | MCU 扭矩 | 车辆状态 |
| --- | ---: | ---: | --- |
| 55.100 s（故障前） | 1 | 142.98 | 车速 160.89。 |
| 55.200 s（Key 置 0） | 0 | 142.41 | 残余扭矩开始下降。 |
| 55.600 s | 0 | 0 | 扭矩归零，车速约 163.03。 |
| 55.900 s（Key 恢复 1） | 1 | 0 | 没有立即恢复驱动。 |
| 60.900 s | 1 | 0 | 此前约 5.0 s 内仍未恢复扭矩。 |

结论：Key 脉冲触发了实际动力切断，切断观测延迟约 0.400 s；Key 回升本身没有使扭矩自动恢复。对防止失灵脉冲后的意外再驱动而言，这是安全行为。若产品需求要求 Key 恢复后自动恢复动力，则该结果需要按需求判为恢复失败；本数据无法确定是否存在关断锁存或外部 VCU 请求被清除。

### 3. 错误唤醒（0 → 1 → 0）

错误唤醒发生于 69.600～70.300 s，Key 高电平持续约 0.700 s。此期间 `Gear_Button=0`、`AccPedal_perc=0%`、`BrakePedal_perc=100%` 保持不变。

| 观察项 | Key 脉冲期间结果 |
| --- | --- |
| MCU/前电机扭矩 | 全部为 0。 |
| MCU / BMS 母线电流 | 约 `1e-5` 量级，接近零。 |
| 车速 | -0.39～0.37 附近小幅波动，可视为静止附近数值噪声。 |
| 制动输出 | BRK 主/辅保持 4/2 V，制动继电器维持激活。 |
| 加速输出 | ACC 主/辅保持 1/0.5 V。 |

结论：错误唤醒没有产生扭矩、电流或车速上升；在当前静止、制动保持的工况下，未发现非预期驱动风险。

## 接口与通道一致性

尽管 Key 故障改变了动力状态，踏板接口仍保持正确映射：

```text
BRK_Main = 1 + 0.03 × clip(BrakePedal, 0, 100)
BRK_Auxi = BRK_Main / 2
ACC_Main = 1 + 0.03 × clip(AccPedal, 0, 100)
ACC_Auxi = ACC_Main / 2
```

- BRK 主/辅映射残差为 0；ACC 主/辅映射残差为 0。
- 两路制动继电器全 796 样本一致，无失配。
- 前电机实际扭矩、前轴扭矩管理量与 MCU 扭矩输出在本记录中同步变化；Key 关断后的动力切断并未被踏板模拟量输出的保留值抵消。

这说明 Key 相关关断位于动力允许/扭矩链路，而不是通过篡改踏板模拟量输出实现。

## 限制信号观察

`MC_MaxToque_Limit_ToBus` 与 `MC_max_Torque_Limit_ToBus` 在 Key 故障前后存在状态变化，但并未呈现一个可直接作为“Key=0”标志的固定值。例如突然熄火后实际扭矩为 0，而前者仍可从约 144 上升至约 157；失灵脉冲恢复后也会继续变化。因此，它们不能单独作为本轮 Key 故障成功与否的判定依据。

更可靠的判定组合是：`Key` 边沿、实际/MCU 扭矩、电流与车速。建议下轮增加 Key 状态机、动力允许状态、VCU 扭矩请求、模型 Reset/Disable、故障诊断位和接触器状态。

## 故障判定

| 检查项 | 判定 |
| --- | --- |
| Key 下降沿后的扭矩切断 | 通过观察，突然熄火约 0.2 s、脉冲故障约 0.4 s 内归零。 |
| 失灵脉冲后的非预期自动恢复 | 未观察到，安全表现通过。 |
| 错误唤醒后的非预期驱动 | 未观察到，安全表现通过。 |
| 踏板模拟量输出与制动继电器一致性 | 通过。 |
| Key 故障状态机、诊断和自动恢复策略 | 无法判定，缺少内部状态与 VCU 请求。 |
| 满足项目级关断时限 | 待确认，需给出允许的最大关断时间阈值。 |

## 下一轮建议

1. 记录 `VCU_TqReqCmd`、Key 状态机、动力允许、接触器、Model_Reset/Model_Disabled 和故障诊断位，区分 Key 锁存与上层扭矩请求清零。
2. 将采样周期提高到 10～20 ms，精确度量 Key 下降沿至扭矩/电流归零的延迟。
3. 分别在静止、低速和高速下重复三类故障，并定义允许的扭矩残留时间和最大允许滑行距离。
4. 对失灵脉冲明确需求：是必须人工重新上电后恢复，还是允许自动恢复；再据此评估 55.9 s 后零扭矩状态。
