# FI-08 钥匙（Key）故障：故障指纹与最小诊断集（20 ms）

## 指纹定义

`+++` 为强置位/恢复，`---` 为强撤除/下降，`0` 为未观察到故障诱发变化，`+→-` 为车速受惯性先继续上升、后转为下降。符号只描述故障导致的增量，不能替代项目级安全阈值。

## 运行中突然熄火：Key 1 → 0

```text
Key                           ---   1 → 0
FMotor.MotTrq / FTrq / RTrq  ---   220–260 ms 内降至故障前 ≤5%
MC_motor_Torque_ToBus         ---   260 ms 内降至故障前 ≤5%
MC_busbar_current             ---   260 ms 内降至故障前 ≤5%
BMS_HVBusCurr                 ---   300 ms 内降至故障前 ≤5%
Vehspeed                      +→-   340 ms 达惯性峰值，随后滑行下降
ACC_Main、BRK_Main、继电器     0     不因 Key 边沿改变
```

这是一条“Key 关断 → 动力撤除 → 电流下降 → 车辆滑行”的观测链。没有记录内部允许状态，故不把 Key 到扭矩的内部机制表述为已证实的单一控制模块。

## 运行中失灵脉冲：Key 1 → 0 → 1

```text
Key 下降沿                     ---   低电平持续 620 ms
前后实际扭矩与 MC 扭矩          ---   220 ms 内降至基线 ≤5%
MC/BMS 母线电流                ---   220 / 260 ms 内降至基线 ≤5%
Key 恢复为 1                   +++   但没有带来扭矩恢复
前后实际扭矩、MC 扭矩           0     Key 恢复后至少 5.12 s 全程为 0
Vehspeed                       +→-   峰值后持续滑行
```

该指纹表示“关断后不自动再驱动”。若需求要求人工重新上电或重新请求扭矩后才允许恢复，则符合安全意图；若需求要求 Key 回升自动恢复动力，则应判为恢复失败。

## 静止错误唤醒：Key 0 → 1 → 0

```text
Key                           脉冲高电平 600 ms
MC/前后实际扭矩                0     全程为 0
MC/BMS 母线电流                0     全程为 0
Vehspeed                       0     -0.392～0.392，静止附近波动
BRK_Main / BrakeOpen1          0     保持 4 V / 2
ACC_Main                       0     保持 1 V
```

在 `Gear=0、Acc=0%、Brake=100%` 工况中，错误唤醒没有形成驱动指纹。该结论不自动外推到有挡位、有油门或无制动的错误唤醒工况。

## 最小诊断集：已记录的 8 个接口

| 层级 | 接口 | 作用 |
| --- | --- | --- |
| 故障源 | `Veh_1.Driver.Key` | 确定下降沿、脉冲宽度、恢复沿和卡高/卡低。 |
| 关键工况 | `Veh_1.Driver.Gear_Button` | 防止把挡位变化误判为 Key 效果。 |
| 关键工况 | `Veh_1.Driver.AccPedal_perc` | 防止把油门撤除误判为 Key 关断。 |
| 关键工况 | `Veh_1.Driver.BrakePedal_perc` | 防止把制动减速误判为动力切断。 |
| 前轴动力 | `Veh_1.PlantModel.PlantModel.Powertrain.FMotor.Motor.MotTrqManagement.FTrq` | 验证前轴实际扭矩是否切断。 |
| 后轴动力 | `Veh_1.PlantModel.PlantModel.Powertrain.RMotor.Motor.MotTrqManagement.RTrq` | 验证后轴实际扭矩是否切断。 |
| 电能响应 | `Veh_1.ToVCU.powerCAN_out.SoftMCUDataToBus.MC_motor_Torque_AND_speed.MC_busbar_current_ToBus` | 验证动力切断是否传至电机功率链。 |
| 车辆响应 | `Veh_1.PlantModel.PlantModel.Vehicle1.Vehspeed ` | 验证滑行、意外再驱动或静止保持。 |

`MC_motor_Torque_ToBus` 与前轴扭矩在本轮同步，`BMS_HVBusCurr_ToBus` 与 MC 电流同向，故不纳入严格最小集；建议在需要跨控制器一致性诊断时保留。

## 最小集不能回答的问题与下一轮必加信号

当前最关键的缺口是“为何 Key=1 后不恢复动力”。下一轮在上述最小集之外，应至少记录：

```text
Model_Disabled
Model_Reset
Veh_1.ToVCU.HW.Relay.Relay25.Model_Disabled_Out
Veh_1.FromVCU.CAN.VCU_Body.GW_VCU_2.VCU_TqReqCmd
Veh_1.FromVCU.CAN.VCU_Power.VCU_MC_TrqCtrl.VCU_Target_output_Torque
Veh_1.FromVCU.CAN.VCU_Power.VCU_Geaeral_CAN1.VCU_Key_Position
Veh_1.FromVCU.CAN.VCU_Body.BCM_1.KeySts
Veh_1.ToVCU.powerCAN_out.SoftMCUDataToBus.MC_General.MC_system_Fault_level_ToBus
Veh_1.ToVCU.powerCAN_out.SoftMCUDataToBus.MC_motor_Torque_AND_speed_MsgEnable.MC_motor_Torque_AND_speed_MsgDisable
```

这些信号可把“Key 输入异常”拆分为模型被禁用/复位、VCU 请求被清除、MC 保护降级或报文失能等互斥诊断路径。

## 诊断判读

| 观测组合 | 诊断方向 |
| --- | --- |
| Key=0，前后扭矩和电流在时限内归零 | 关断动力响应有效。 |
| Key=0，仍有持续正扭矩或显著电流 | 动力允许/扭矩关断异常，高风险。 |
| Key 恢复后扭矩仍为零 | 需利用 Model 状态、VCU 请求和故障位区分锁存、请求未恢复或保护状态。 |
| Key=1，Gear/Acc 有效，扭矩自行恢复 | 需评估是否存在不期望的自动再驱动。 |
| 错误唤醒时扭矩、电流或车速上升 | 错误唤醒安全策略异常。 |
